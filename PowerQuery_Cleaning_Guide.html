Assess the data · Step 1
First impressions of a new dataset
Before cleaning anything, just look. This stage is about building a mental map of what you're dealing with — not fixing anything yet. Do this for any dataset you're ever handed, not just this one.
1
Check the basic shape of the data
▼
▶ Bottom status bar in Power Query / Excel
  1. How many rows? How many columns? In Power Query this shows in the bottom-left status bar.
  2. What does each column appear to represent? Just read the header names first.
  3. Is there one row per "thing" (one row per job posting, one row per application), or could rows represent something else (totals, headers, merged cells)?
💡 For your job market data: 104 rows in postings, 2,661 in applications. Knowing this upfront means you'll notice immediately if cleaning accidentally drops or duplicates rows later.
2
Scroll through 20-30 rows manually
▼
  1. Don't trust the column name — read the actual values in each cell.
  2. Look for anything that surprises you: stray symbols, inconsistent capitalization, text where you expected numbers, numbers where you expected text.
  3. Note down (mentally or on paper) every "huh, that's odd" moment. These become your cleaning checklist later.
⚠️ This is exactly how you'd first notice things like a salary column containing the word "Negotiable", or a date column mixing "2026-01-04" with "Jan 4, 2026". Skipping this step means you find these problems one at a time, mid-cleaning, instead of all at once upfront.
Assess the data · Step 2
Column-by-column profiling
This is the systematic part. For every single column, you check its data type, its distinct values, and whether it has blanks. Power Query has built-in tools that make this almost automatic.
1
Turn on Column Distribution and Column Quality
View tab
▼
▶ View tab → Data Preview group → check Column Distribution, Column Quality, Column Profile
  1. Open your query in Power Query Editor.
  2. Go to the View tab.
  3. In the "Data Preview" group, tick all three checkboxes: Column Quality, Column Distribution, Column Profile.
  4. Small bars and stats now appear under every column header — this is your profiling dashboard.
What each one tells you
FeatureWhat it shows
Column Quality% Valid, % Error, % Empty — a quick health check
Column DistributionHow many distinct values, how many unique values, mini bar chart
Column ProfileClick a column to see full value distribution + stats (min, max, average for numbers)
💡 By default Power Query only profiles the first 1000 rows. For datasets under ~10,000 rows (like yours), click "Column profiling based on top 1000 rows" in the bottom status bar and switch it to "the entire data set" for accurate counts.
2
Use the column header dropdown to see every distinct value
Column header → dropdown arrow
▼
  1. Click the small dropdown arrow on any column header.
  2. A checklist of every distinct value in that column appears, with counts.
  3. For categorical columns (like work_setup, gender, education), this immediately reveals every spelling variant.
  4. For free-text columns (like salary or job_description), this list will be very long and messy — that's your signal it needs a different cleaning approach (extraction, not just standardizing).
Example: what this revealed in work_setup
WFH (12) remote (8) Remote (34) On-site (15) Onsite (20) Hybrid (15)
3
Check the data type icon on every column
▼
  1. Look at the small icon to the left of each column name (ABC = text, 123 = whole number, calendar = date).
  2. Ask: does this match what the column should be? A date column showing ABC means it's stored as text and needs parsing. A "salary" column showing ABC instead of 123 means it has non-numeric characters mixed in.
  3. Make a note of every column where the icon doesn't match the expected type — these need fixing before you can do math, filtering, or date logic on them.
💡 This single check is what told us posted_date and salary both needed custom formulas — the ABC icon was a dead giveaway that something was off.

Assess the data · Step 4
Write a cleaning checklist, in order
Now turn your classified list into an ordered plan. Order matters — doing things in the wrong sequence can cause later steps to fail or produce wrong results.
1
The general priority order
▼
  1. Remove duplicates first — cheap, low-risk, and avoids cleaning the same bad row twice.
  2. Trim and fix formatting noise — spaces and casing issues can hide as "different values" until removed.
  3. Standardize categories — now that formatting noise is gone, Replace Values works cleanly.
  4. Fix data types — dates and numbers, now that the underlying text is clean.
  5. Handle structural extraction last — parsing salary or extracting skills depends on having clean, well-typed source columns to work from.
  6. Decide on missing values — null them out, or flag them, once you understand the rest of the data's shape.
⚠️ Notice this is the exact order we followed for your job postings table: dedupe → trim → clean titles → standardize categories → null blanks → parse dates → parse salary → extract skills. That wasn't arbitrary — each step built on a cleaner foundation than the last.
2
A simple checklist template you can reuse
▼

For any new dataset, write one line per column using this template, then sort by the priority order above:

[Column name] — [category of problem] — [planned fix] — [priority: 1-6]

Example for one row from this project: work_setup — inconsistent categories — Replace Values (WFH→Remote, On-site→Onsite) — priority 3

Assess the data · Step 5
Validate after cleaning
After cleaning, re-run the exact same checks you did during profiling, on the same columns. If something still looks wrong, you'll catch it now instead of after building your dashboard on top of it.
1
Re-check Column Quality and Column Distribution
▼
  1. With Column Quality still turned on (View tab), check that every column shows close to 100% Valid, 0% Error.
  2. Check Column Distribution — the "distinct values" count for categorical columns should now match the number of clean categories you expected (e.g. 3 for work_setup, not 6).
  3. Click the dropdown on each previously-messy column and confirm only the clean values remain.
2
Spot-check row counts and a few individual rows
▼
  1. Confirm the row count matches what you expect (e.g. 100 after removing 4 duplicates, not accidentally 96 or still 104).
  2. Pick 3-5 rows you remember being messy from your first scroll-through (Step 1) and check they're now clean.
  3. If anything still looks wrong, click the relevant step in the Applied Steps panel to inspect or fix it — don't just patch it with another step on top.
🎉 Once validation passes, you're ready to move into the actual hands-on cleaning steps below — which walk through exactly how to fix each of the 6 problem categories for this dataset.
Getting started
How to open Power Query Editor
Power Query is where all data cleaning happens. You never touch the raw CSV directly — everything is done through steps that Power Query records automatically.
1
Load your CSV files into Power BI
▼
▶ Home tab → Get Data
  1. Open Power BI Desktop. On the Home ribbon, click Get Data.
  2. Choose Text/CSV from the list.
  3. Browse to your raw_job_postings.csv file and click Open.
  4. A preview window appears. Click Transform Data — not Load. This takes you directly into Power Query Editor.
  5. Repeat for raw_applications.csv: Home → Get Data → Text/CSV.
⚡ Always click Transform Data, not Load. If you click Load by mistake, go to Home → Transform Data to open the editor afterwards.
2
Get familiar with the Power Query layout
▼
  1. Queries pane (left) — lists your tables. You'll see raw_job_postings and raw_applications. Click one to work on it.
  2. Data preview (center) — shows your rows. Column headers have a type icon on the left (ABC = text, 123 = number, calendar = date).
  3. Applied Steps panel (right) — every cleaning action you take appears here as a named step. You can click any step to undo or inspect it.
  4. Ribbons (top) — Home, Transform, Add Column, View. Most cleaning is in Home and Transform.
💡 The Applied Steps panel is your safety net. If a step breaks something, just click the X next to it to delete it and try again.

Trim whitespace from all columns
Many columns have invisible trailing spaces — things like "Full-time " instead of "Full-time". These cause silent bugs where "Full-time" ≠ "Full-time " in filters. Trim removes them.
1
Select all columns, then Trim
Transform tab
▼
▶ Transform tab → Format → Trim
  1. Click the first column header (job_id).
  2. Hold Shift and click the last column (job_description) to select all columns.
  3. Go to the Transform tab in the ribbon.
  4. Click Format → Trim.
💡 Do this for raw_applications too — select all its columns and Trim the same way. It's always safe to trim text columns.

Job Postings · Step 6
Replace blank company & location with null
A few rows have empty company or location cells. In Power BI, blank text ("") and null are different — null is the proper "no value" marker and works better with filters and visuals.
1
Replace empty string with null
Transform tab → Replace Values
▼
▶ Click company column → Transform → Replace Values
  1. Select the company column.
  2. Click Replace Values.
  3. "Value to find": leave it completely empty (don't type anything).
  4. "Replace with": type null (lowercase).
  5. Click OK.
  6. Repeat the same steps for the location column.
⚠️ Make sure "Replace with" says exactly null in lowercase. Power Query will convert it to a proper null value, shown as italicised null in the preview.
Job Postings · Step 7
Parse posted_date into a real Date
The date column contains 4 different formats mixed together. Power Query can't auto-detect them all — we need a Custom Column formula that handles each format explicitly.
1
See what formats exist in the data
▼
Format nameExample from dataPattern
ISO2026-05-01yyyy-MM-dd
US02/26/2026MM/dd/yyyy
LongFeb 27, 2026MMM d, yyyy
Short04-Jan-26dd-MMM-yy
2
Add a Custom Column with the date formula
Add Column tab → Custom Column
▼
▶ Add Column tab → Custom Column
  1. Go to the Add Column tab in the ribbon.
  2. Click Custom Column.
  3. Name the new column: posted_date_clean
  4. Delete any existing formula and paste this:
let s = Text.Trim([posted_date]) in if Text.Length(s) = 10 and Text.At(s, 4) = "-" and Text.At(s, 7) = "-" then Date.FromText(s) else if Text.Length(s) = 10 and Text.At(s, 2) = "/" then Date.FromText(s, [Format="MM/dd/yyyy"]) else if Text.Contains(s, ",") then Date.FromText(s, [Format="MMM d, yyyy"]) else if Text.Length(s) = 9 and Text.At(s, 2) = "-" then Date.FromText(s, [Format="dd-MMM-yy"]) else null
  1. Click OK. A new column posted_date_clean appears on the right.
  2. Click its column header → go to Transform tab → Data Type → Date.
  3. Now right-click the original posted_date column → Remove.
  4. Right-click posted_date_clean → Rename → type posted_date.
Result — all dates now look the same
2026-01-04 2026-02-26 2026-04-06
💡 If any row shows an Error in the new column, click that cell to see which date string caused it. You can add another else if line for that format.
Job Postings · Step 8
Parse salary into numbers
The salary column is the messiest. It has 4 free-text formats plus blanks and "Negotiable". We extract salary_min, salary_max, and a salary_midpoint as whole PHP numbers using Custom Column formulas.
1
Understand the 4 salary formats
▼
FormatExampleLogic
Range with "to"107,000 to 137,000 PHP per monthSplit on " to "
₱K range₱115.0K - ₱147.0K /moExtract numbers × 1000
PHP dash rangePHP 126,000-161,000 monthlySplit on "-"
Up to (max only)Up to ₱37,000/monthmin = null, max = number
Blank / Negotiablenull / NegotiableBoth null
2
Add salary_min custom column
Add Column → Custom Column
▼
▶ Add Column tab → Custom Column → name it salary_min
let raw = Text.Trim([salary]), upper = Text.Upper(raw), isK = Text.Contains(raw, "K"), nums = List.Select( List.Transform( Text.SplitAny(Text.Remove(raw, {"₱","K","k"}), " ,to–-/"), each try Number.FromText(Text.Remove(_, {","})) otherwise null ), each _ <> null and _ >= 10 and _ <= 500 ), converted = List.Transform(nums, each if isK then _ * 1000 else _) in if upper = "NEGOTIABLE" or raw = "" then null else if Text.StartsWith(upper, "UP TO") then null else if List.Count(converted) >= 2 then List.Min(converted) else if List.Count(converted) = 1 then List.First(converted) else null

After clicking OK, change the column data type to Whole Number.

3
Add salary_max custom column
Add Column → Custom Column
▼
▶ Add Column tab → Custom Column → name it salary_max
let raw = Text.Trim([salary]), upper = Text.Upper(raw), isK = Text.Contains(raw, "K"), nums = List.Select( List.Transform( Text.SplitAny(Text.Remove(raw, {"₱","K","k"}), " ,to–-/"), each try Number.FromText(Text.Remove(_, {","})) otherwise null ), each _ <> null and _ >= 10 and _ <= 500 ), converted = List.Transform(nums, each if isK then _ * 1000 else _) in if upper = "NEGOTIABLE" or raw = "" then null else if List.Count(converted) >= 1 then List.Max(converted) else null

Change data type to Whole Number.

Add salary_midpoint custom column
Add Column → Custom Column
▼
▶ Add Column tab → Custom Column → name it salary_midpoint
if [salary_min] = null and [salary_max] <> null then [salary_max] else if [salary_min] <> null and [salary_max] <> null then Number.RoundUp(([salary_min] + [salary_max]) / 2, 0) else null

Job Postings · Step 9
Extract skills_raw from job_description
Every job description follows the same pattern: "Responsibilities include working with X, Y, Z. The ideal candidate…" — we extract the skill list between those two markers.
1
Add skills_raw custom column
Add Column → Custom Column
▼
▶ Add Column tab → Custom Column → name it skills_raw
let desc = [job_description], marker = "Responsibilities include working with ", endTag = ". The ideal", startPos = Text.PositionOf(desc, marker), afterStart = Text.Middle(desc, startPos + Text.Length(marker)), endPos = Text.PositionOf(afterStart, endTag), skillStr = Text.Start(afterStart, endPos) in if startPos >= 0 and endPos > 0 then skillStr else null
